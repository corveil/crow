## [Unreleased]

### Added

- CROW-938 — Detect when a newer Crow build is available by comparing the stamped `gitSha` against `corveil/crow` `main` (no release tags required). `crowd` owns the GitHub compare call, caches the result, and checks at most once per daemon start plus every ≥6 hours (configurable, opt-out via `versionUpdate.enabled`). Surfaces: `crow version --check` / `crow version check` (human summary with exit codes), `crow version get|set`, Settings → About (status + Check now), and a dismissible web banner when behind. Offline, rate-limited, `dev`, or unknown SHAs report `unknown` — never a false up-to-date.

## [0.2.0] - 2026-08-05

Backfill of merged PRs since the 0.1.0 release, grouped by theme.

### Web UI

- CROW-936 — The web UI has real URLs. Selecting a session, switching terminal tabs, opening the Ticket/Reviews/Allowlist/Scorecard boards, and each Settings tab are all addressable, so views can be linked, bookmarked, and survive a reload, and Back/Forward move between them instead of leaving the app. Routing is **hash-based** ([ADR 0018](docs/adr/0018-web-client-hash-routing.md)) — `crowd` serves the client from a table of exact literal paths with no catch-all, so under History-API routing an *authenticated* cold load of `/sessions/<id>` would 404 in the router, while an unauthenticated one renders the login page (the auth middleware answers any navigational GET with a 200), and the Tauri shell's `location.reload()` would hit the same 404. A fragment never reaches the server, so no Swift file changes. Routed navigation goes *through* the existing `selectSession` / `selectBoard` / `switchTerminal` / `openSettings` entry points rather than beside them, and `navigate()` no-ops on an unchanged hash so applying a route can't push a second history entry. Two shapes the ticket's sketch got wrong are corrected: there are four boards, not two, and Jobs is a Settings tab (`#/settings/jobs`), not a screen. A URL naming a session that no longer exists now lands on an explicit not-found card with a way back — Crow's retention reaper deletes completed sessions, so a dead link is the normal fate of a shared URL, and previously it left a blank header, an orphan "+" tab, and a frozen terminal; the same guard now also catches a session reaped *while you're viewing it*, which nothing checked before. Deep links survive the login round-trip: the auth middleware serves the login page at the requested URL, so the fragment is still in the address bar and is handed back once the password is accepted. Only the addressable view is encoded — scroll position, open menus, selection mode, and board filters stay out of the URL.

- #879 — Agent pickers now show **all** known coding agents, greying out (and disabling) the ones whose binary isn't on the daemon's PATH instead of hiding them — so a shipped-but-uninstalled agent (e.g. Antigravity) is discoverable, with a "not found on PATH — install it and restart Crow to enable" tooltip explaining why it's disabled. Covers the new-manager launch menu, the agent-handoff menu, and every Settings selector (Default agent + the four per-action overrides). `list-agents` gained `available` + `binary` fields; the launch gate is unchanged, so an off-PATH agent still can't be launched or handed off to.
- #752 — Multi-select "Start Working (N)" on the tickets board now fires a single `batch-work-on-issues` RPC, so the Manager runs one `/crow-batch-workspace url1 url2 …` (parallel setup) instead of N separate `/crow-workspace` submissions.
- #613 — Left pane paints chrome + skeleton (or cached last-known) session rows on first load before `list-sessions` returns, then swaps in real rows without a blank flash.
- #768 — Notifications for automation events are back after the native→web move: auto-workspace created, auto-merge enabled, auto-rebase pushed, auto-rebase conflicts, and config reloaded. The daemon pushes each over the existing `/rpc` socket at the moment the watcher acts; the web UI chimes and posts a browser notification, with per-event Enabled / sound / system toggles under Settings → Notifications. Conflict events use a distinct, harsher tone and are never suppressed by the "you're looking at it" focus rule.

### Automation

- CROW-876 — `mark-in-review` now moves the provider's board, not just Crow's session status. `IssueTracker.markInReview` did the real work but had no callers: its only entry point was `AppState.onMarkInReview`, which nothing assigned once the macOS app was retired (ADR 0010), so the verb silently degraded to `set-status inReview` while the web menu still gated it on `can_set_project_status` — promising a board move that never happened. That left the board pipeline with two of three legs wired (session start → In Progress via `setup.sh`, issue done → Done via `closeTask`), and `crow resync-jira` as the only route to In Review. The handler now calls the tracker like `mark-issue-done` does: board first, so a failed transition exits non-zero instead of leaving the session marked, then the session write. Preconditions and provider failures come back as typed `SessionActionError`s rather than a silent early return, which also fixed a latent defect the method carried unnoticed while dead — it resolved its backend from the bare provider enum, dropping the host for self-hosted GitLab/Corveil. A provider with no In Review status to move *to* is deliberately **not** an error: nothing was ever going to move, so the session still transitions and the response carries an additive `warning`. That covers GitLab and, more importantly, any GitHub board whose column isn't named "In Review"/"Review" or whose Status field is unset — throwing there would have turned a fix into a breakage for a large slice of real boards. **New side effect:** on a GitHub repo with no project board at all, `mark-in-review` now applies the `crow:in-review` fallback label (#706, #790) — a repo write this verb never made before. `docs/automation.md` also claimed a "PR opened → In Review" transition that no code performed; corrected rather than implemented.
- CROW-921 — A changes-requested PR whose findings were actually fixed no longer parks in `changesRequested` forever. The loop had two states and needed three: the only thing that re-requested review was a sentence inside the changes-requested prompt, and that prompt is reachable only while the agent still *owes* a fix — so it could never fire once the fix landed, and with the host's review request already consumed the PR was invisible to the reviewer's queue and to `review-requested:@me` alike. `PRStatus.changesRequestedState` now names all three (`needsRefine` / `awaitingReRequest` / `awaitingReviewer`) and both `needsRefine` and the new `applyAutoReRequestReview` watcher derive from it, so they can't drift apart. The third state is scoped to *the reviewers who requested changes*, not to "does the PR have any pending request" — requests are per-reviewer and the host clears only the submitting one, so a PR routinely carries A's blocking verdict alongside B's still-pending original request, and a PR-wide reading would silence both halves of the loop for exactly the multi-reviewer PRs this is meant to rescue. The watcher calls `gh pr edit --add-reviewer` from the daemon rather than asking the agent to — a one-line API call routed through an agent turn costs a turn's tokens, can't be verified, and would re-inherit the gate that caused the dead-end; the prompt hint stays as belt-and-braces, since re-requesting an already-requested reviewer is a no-op. Gated by `autoRespond.autoReRequestReview` (**on** by default, alongside `respondToChangesRequested`, because the prompt has always instructed the agent to do this), readable and writable via `crow automation get|set --auto-re-request-review`. Two supporting fixes: `lastSubstantiveCommitAt` now anchors on the commit **author** date rather than the committer date, closing the documented CROW-508 rebase gap in both directions — a rebase restamp no longer suppresses a genuine needs-refine, nor fires a no-op review round at a reviewer; and every *suppressed* needs-refine evaluation is now logged with the gate that held it (`needs-refine: #N gated (reason=…, state=…, lastCR=…, lastCommit=…, reviewerReRequested=…, idle=…, cooldown=…)`), rate-limited to changes plus an hourly heartbeat, where previously only firing was logged and a stuck PR left no trace at all.
- #888 — The `crow:merge` label no longer lands in silence. When Crow's auto-merge watcher can't act on a labeled PR, the reason now reaches the UI instead of only `crowd-automation.log`: `list-sessions-live` carries an additive `auto_merge_state` (`{phase, reason, message, permanent}`), and the sidebar PR pill and detail header render it as a tinted ⛙ chip in the shared PR glyph vocabulary — green enabled, purple merged by Crow, orange retrying, red permanently blocked, grey watcher-off — with the full sentence in the tooltip and `aria-label`. The twelve skip reasons (previously six enum cases plus six ad-hoc string literals) are one enum carrying the same grep-stable log strings plus a human sentence and a permanence flag; reasons the pill already renders (conflicts, changes-requested, no label) are deliberately not republished. Repo policy is now read proactively from GraphQL `Repository.autoMergeAllowed` on the fetch Crow already makes, rather than discovered by failing `gh pr merge --auto` and string-matching the error, and a repo with GitHub's "Allow auto-merge" disabled gets a **direct squash-merge fallback** for PRs that are OPEN, non-draft, `CLEAN`, `MERGEABLE`, checks-green, approved, and Crow-authored. A permanent block fires a new **Auto-Merge Blocked** notification, once per PR rather than once per 60s poll. `crow add-merge-label` still applies the label and still returns `ok: true`, but now includes a `warning` when the label can't lead to a merge. The bare untinted ⛙ in the session row's trailing cluster is folded into the PR pill, so "Crow armed this" and "Crow gave up on this" no longer render identically.
- #137 — Session analytics emitted via Claude Code's OpenTelemetry exporter (configure via `CLAUDE_CODE_ENABLE_TELEMETRY` and `OTEL_EXPORTER_OTLP_ENDPOINT`).
- #163 / #165 — Add `remoteControlEnabled` setting; new sessions launch with `--rc` so they can be driven from claude.ai or the mobile app. The `/crow-workspace` skill honors the setting.
- #182 — Auto-complete now requires positive evidence that the session was worked before flipping to Completed; prevents idle sessions being marked done by an unrelated PR merge.
- #189 — Manager terminal launches in `--permission-mode auto` by default so orchestration commands (`crow`, `gh`, `git`) skip per-call approval. Toggle at Settings → Automation → Manager Terminal.
- #209 — Per-workspace opt-in to auto-start review sessions when a PR becomes reviewable.
- #211 — Auto-create a workspace when an issue assigned to you carries the `crow:auto` label.
- #213 — Auto-suggest opening a PR when a session completes its work but no PR is linked yet.
- #214 — Optional auto-respond toggles: when enabled, Crow types an instruction into the session's Claude Code terminal in response to changes-requested reviews and failed CI checks. Off by default.
- #222 — PRs opened from a Crow session are auto-labeled `crow:auto`.
- #228 — Settings split into discrete tabs; every automation toggle lives under Settings → Automation. New `docs/automation.md` covers the full lifecycle.
- #327 — Scheduled Jobs scope to a workspace + repo, where the repo picker is populated from the workspace's provider by expanding its "Always Include Repos" specs (`owner/*` globs or `owner/repo` slugs). Repos not yet checked out are cloned on demand when the job fires.
- #461 — Remove the PR auto-label workflow (reverts #222); `crow:auto` on a PR was a no-op since only assigned issues consume the label. The label itself stays for issue auto-launch.
- #814 — General-tab settings are drivable from the CLI: `crow telemetry get/set`, `crow cleanup get/set`, `crow ui get/set`. Each `set` is a patch that echoes the resulting subtree plus `restart_required` — telemetry's enabled/port need a `crowd` restart, cleanup applies within a board poll, and the sidebar preference repaints connected browsers within ~2s. Riding along: the three settings structs now decode per-key with defaults, and config writers refuse to overwrite a `config.json` that exists but won't decode, closing a path where one malformed block could silently reset every workspace, job, and credential to defaults.
- #813 — Notification settings from the CLI: `crow notifications get|set` reads and writes `AppConfig.notifications` — the global mute / sound / system-notification toggles and each of the ten events' `enabled`, sound, system-notification, and sound-name settings (validated against the 14 built-in sounds). Writes go through the shared config lock, and the `configReloaded` refresh above is awaited before the event chimes, so a mute applied from the CLI also silences the notification announcing it. The `notifications` block now decodes per-key with defaults too, so a partial hand edit no longer fails the whole config.
- #604 — Full job management from the CLI: `crow job list/get/add/edit/enable/disable/run/delete/duplicate`. Mutations route through the running app's live config (picked up by the scheduler and Settings UI without a restart), and `crow job run --id` fires a job immediately regardless of its schedule or enabled flag, returning the launched session/terminal ids.
- #810 — Workspace and automation defaults from the CLI: `crow defaults get|set` reads and writes `AppConfig.defaults` — provider, forge CLI, branch prefix, the review/ticket repo exclusions and ignored review labels, and the binary path overrides. The three lists are edited incrementally (`--add-…` / `--remove-…` / `--clear-…`, matched case-insensitively like the board filters themselves) instead of by replacement, so excluding one more repo doesn't mean restating the list. `--binary` merges into the map rather than replacing it, and is local-only — binary overrides are absolute paths that execute at the next agent launch — and returns `restart_required`, including when removing one, since nothing re-scaffolds `.claude/bin` until the next launch. `--cli` is exposed alongside `--provider` because the two are read as an independent pair and the web UI has no `cli` field at all, so a provider flip previously left a broken pair with no way to fix it short of hand-editing `config.json`.
- #812 — Settings → Automation toggles from the CLI: `crow automation get|set` reads and writes the eleven booleans behind the tab — the five auto-permission modes (including the Jobs one, so they read as a group), remote control, commit attribution, the `crow:auto` / `crow:merge` watchers, and the three `autoRespond` toggles. Booleans take an explicit `true`/`false` because six of the eleven default to on, so a bare flag could never turn one off. Nothing needs a `crowd` restart — the daemon re-reads config lazily rather than holding a snapshot — except `managerAutoPermissionMode`, which is baked into the Manager terminal's stored command and so reports `manager_restart_required` and points at `crow restart-manager`. The tab's three board-filter lists are `AppConfig.defaults` fields and belong to `crow defaults` (#810); `get` surfaces the derived `effective_exclude_review_repos` (the global list unioned with every workspace's own) so the filter that actually applies is visible from either verb.
- #817 — Board and workflow actions are no longer web-only: `crow list-tickets`, `list-reviews`, `refresh-tickets`, `work-on-issue`, `batch-work-on-issues`, `start-review`, `create-manager`, and `quick-action` drive the same RPCs as the board buttons. The read verbs print the board payload verbatim for `jq`; `batch-work-on-issues` takes repeatable `--url` plus `--urls-file -`, so a ticket list pipes straight out of `gh issue list`.

### Internal

- CROW-876 — Deleted thirteen `EngineRouter` routes that returned an unconditional `{"ok": true}` for nothing: the five session-lifecycle verbs plus `quick-action`, `work-on-issue`, `start-review`, `promote-allowlist`, `refresh-tickets`, `refresh-allowlist`, `create-manager`, and `run-job`. Every one was shadowed by a daemon handler of the same name (`CommandRouter` reaches a fallback only for an *un*registered method), and twelve of their thirteen `AppState` callbacks were never assigned anywhere — so even if routing changed, they would have reported success for a no-op. This is the same false-success shape #868 removed from the daemon path. The twelve orphaned callbacks went with them; `onCompleteSession` stays, since `IssueTracker` still uses it for auto-complete-on-merge. `SessionLifecycleRPC.requireTicketURL` was also retired — `mark-in-review` was its last caller, and that check now lives in `IssueTracker` alongside the provider, Manager, and session-existence guards, restoring the "one source of truth, not two" invariant the type documents.

[[String: Any]]` cast is element-wise and all-or-nothing — one `null` made the whole array cast fail, so the parser dropped 8 perfectly good PRs to salvage nothing. The same trap sat on all 16 GraphQL connection walks in the two GitHub backends, including the assigned-issues board, which emptied the same way. All of them now go through a `LenientJSON` helper that filters unresolvable elements instead of failing the array. Riding along: `prStates` (the stale/session-linked PR backfill) now requests `statusCheckRollup`, so a PR past `viewer.pullRequests(first: 50)` — or one in a restricted org, which is a *permanent* hole in that connection — can show CI state at all; and it recovers its accessible aliases under SAML instead of letting one blocked repo throw away every other PR's state in the batch. One behavior change to note: an issue whose project board has a SAML-nulled item is now correctly seen as being on a board, so a missing Status option raises `unimplemented` rather than quietly writing a `crow:in-review` label.

## [0.1.0] - 2025-04-05

Initial open-source release of Crow.

### Added

- Native macOS application with ticket board, terminal management, and GitHub integration
- Embedded Ghostty terminal with multi-tab support per session
- Session-based workflow management (create, pause, resume, archive)
- Git worktree management with orphan worktree recovery
- GitHub integration with PR status tracking and project board sync
- "In Review" button to update GitHub Project status from the app
- Claude Code hook event system for automatic session activity tracking
- Notification system with configurable sounds and macOS notifications
- "Open in VS Code" and "Open Terminal" buttons for session worktrees
- CLI tool (`crow`) for session, terminal, and metadata management via Unix socket RPC
- `crow setup` command for first-time configuration
- Makefile for build automation (`make build`, `make release`)
- Corveil branding with styled About page showing git commit SHA
- Configurable sidebar with option to hide subtitle lines
- Ticket page redesign with search, sort, and done state filtering
- Claude Code allow list aggregation and promotion across worktrees
- Comprehensive README with setup guide, architecture docs, and CLI reference
- Contributing guide, issue templates, and PR template
- Security audit and open-source readiness documentation

### Fixed

- Ghostty terminal mouse position offset
- UI blocking during GitHub polling and terminal resize on display change
- Merged PR status not detected on app restart
- Crash when reopening About or Settings window
- Disconnected hooks for CLI-created sessions
